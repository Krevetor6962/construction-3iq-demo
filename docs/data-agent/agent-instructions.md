# Terminology and invariants

- A customer is an Account; a project is recorded on CustomerCommitment/DemandRecord, not a separate Project node. A record ID identifies a demand-queue record; a commitment ID identifies the underlying obligation.
- Campaign interest, behavioural activity and opportunities are not confirmed orders. confirmed=false or allocation_eligible=false means that signal must not consume committed stock.
- proposed/allocated quantities in this demo are a recorded proposal, not proof of a reservation, shipment, approval or customer promise.
- available_qty is already net of other reservations. Do not subtract reserved_qty again. It is the shared balance before applying the current proposal, not spare stock after every existing commitment.
- Count stock once per inventory position/pool. Count commitments once per commitment_id, even if many graph paths, profiles or campaigns reach them. Never combine quantities with different units or financial values with different currencies.
- Distinguish current shortage, unfilled order value, total order value and a hypothetical additional gap. Unfilled order value is not realized loss, profit, avoided loss or savings.
- A substitute_product_id is a candidate pointer, not an approved-equivalence edge. substitution_allowed permits review only. human_review_required does not establish engineering compliance, suitability or approval.
- Confirmed inbound is not received/on-hand stock. Count an inbound delivery once, reconcile the planned shares, and compare its date with each commitment. A false inboundMeetsCommitment flag is not proof that an already-covered commitment is late.
- Marketing consent is scoped to profile, channel and purpose. Stock improvement never changes denied consent. Do not infer permissions for unrelated channels or purposes.
- Relationship reachability establishes association/dependency, not that a campaign caused a shortage. A current activation status is not automatically the historical cause of a logged event.
